# النظام الحكومي لإدارة الموارد

نظام إدارة مستودع حكومي متكامل (استلام / تسليم / مخزون / تقارير) مبني على **React + TypeScript + Vite + Tailwind CSS** مع **Supabase** لقاعدة البيانات والمصادقة والصلاحيات (PostgreSQL + Auth + RLS).

## المزايا الرئيسية

- **واجهة عربية كاملة (RTL)** بتصميم احترافي هادئ مناسب للأنظمة الإدارية الحكومية.
- **صفحة ترحيب (Splash)** تُعرض مرة واحدة عند فتح التطبيق (3 ثوانٍ) وتحترم إعداد تقليل الحركة.
- **تسجيل دخول آمن** عبر Supabase Auth برقم الهاتف أو اسم المستخدم، مع إظهار/إخفاء كلمة المرور.
- **4 وظائف رئيسية** في الشاشة الرئيسية: استلام الموارد، تسليم الموارد، المخزون، التقارير.
- **حقول ذكية تتغير حسب نوع المورد** (سيارات / أجهزة كهربائية / ملابس / محروقات...) بدون تعديل الكود.
- **قوائم مترابطة** (النوع ← اسم المورد) مع خيار «إضافة مورد جديد» دون فقدان بيانات النموذج.
- **عمليات ذرية** على مستوى قاعدة البيانات: يمنع الصرف بما يتجاوز الرصيد، ويمنع تكرار الحفظ عند الضغط المتعدد عبر مفتاح عدم التكرار (idempotency key).
- **أصول فردية قابلة للتتبع** (سيارات وأجهزة برقم تسلسلي) منفصلة عن المخزون الاستهلاكي.
- **سجل تدقيق** لكل العمليات مع آلية إلغاء/تصحيح موثقة (تحفظ الأصل + سبب + المستخدم + التاريخ).
- **تقارير رسمية** قابلة للطباعة والتصدير PDF و Excel.
- **صلاحيات مطبقة على قاعدة البيانات** عبر RLS، وليس إخفاء أزرار في الواجهة فقط.

```
├── vercel.json         # إعداد النشر
└── .env.example        # مثال على متغيرات البيئة
```

## إعداد المشروع محلياً

### 1) تثبيت الاعتماديات

```bash
npm install
```

### 2) إعداد قاعدة البيانات (مطلوب مرة واحدة)

في لوحة Supabase: **SQL Editor** ثم نفّذ الملفات بالترتيب:

1. `supabase/migrations/001_init_schema.sql` — إنشاء الجداول والعلاقات والفهارس
2. `supabase/migrations/002_rls_policies.sql` — تفعيل وتطبيق سياسات الصلاحيات
3. `supabase/migrations/003_functions.sql` — الدوال الذرية (استلام/تسليم/إلغاء/أصول)
4. `supabase/migrations/004_seed_data.sql` — بيانات التهيئة (تصنيفات وموارد ووحدات)

أو باستخدام Supabase CLI:

```bash
supabase link --project-ref mlqhupcwhveqddyagvuz
supabase db push
```

### 3) متغيرات البيئة

```bash
cp .env.example .env.local
```

ثم حدّث القيم في `.env.local`. **لا تستخدم Service Role Key في الواجهة أبداً.**

### 4) تشغيل التطبيق

```bash
npm run dev
```

## إنشاء أول حساب مدير

بعد تنفيذ المخطط:

1. في لوحة Supabase: **Authentication > Users > Add user** — أنشئ مستخدماً بالبريد وكلمة مرور.
2. نفّذ في SQL Editor (استبدل البريد):

```sql
insert into public.profiles (id, email, full_name_ar, role_id, is_active)
select u.id, u.email, 'مدير النظام', r.id, true
from auth.users u, public.roles r
where u.email = 'your-admin@example.com'
  and r.name_ar = 'مدير النظام'
on conflict (id) do update set role_id = excluded.role_id, is_active = true;
```

بعد ذلك يمكن للمدير إنشاء بقية المستخدمين من صفحة **المستخدمون والصلاحيات** داخل النظام.

## الاختبارات

```bash
# اختبارات الوحدة (تعمل بدون قاعدة بيانات)
npm run test

# اختبارات التكامل مقابل قاعدة البيانات الفعلية
# أضف في .env.local:
#   TEST_USER_EMAIL=admin@example.com
#   TEST_USER_PASSWORD=your-password
npm run test -- integration
```

اختبارات التكامل تتحقق فعلياً من:

- الاستلام وزيادة الرصيد
- التسليم وخصم الرصيد
- **منع الصرف بما يتجاوز المتوفر**
- **منع تكرار الحفظ عند الضغط المتعدد** (idempotency)
- تسجيل المستلم/المنفذ/التاريخ في الحقول الصحيحة
- **التعامل مع عمليتي صرف متزامنتين** دون خرق الرصيد
- صحة التقارير مقارنة بحركات المخزون
- إضافة نوع جديد وحفظه وظهوره في القوائم

## النشر على Vercel

```bash
npm i -g vercel
vercel --prod
```

أو من لوحة Vercel: **Import Git Repository** ثم أضف متغيرات البيئة في Project Settings:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

> ⚠️ تأكد أن ملف `.env.local` غير مرفوع إلى GitHub (موجود في `.gitignore`).

## الصلاحيات

| الدور | الصلاحيات |
|---|---|
| مدير النظام | كل الصلاحيات |
| أمين المستودع | استلام، تسليم، مخزون، موارد، تقارير، تدقيق |
| موظف استلام | استلام وعرضه |
| موظف تسليم | تسليم وعرضه |
| معتمد العمليات | عرض، تقارير، تصحيح/إلغاء الحركات، تدقيق |
| قراءة وتقارير فقط | مخزون وتقارير |

تُفحص الصلاحيات داخل قاعدة البيانات في كل دالة عبر `public.has_permission()`, ويمكن للمستخدم امتلاك أكثر من صلاحية عبر الدور.
